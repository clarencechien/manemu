# Design.md — manemu(まねむ)設計文件(對應 mockup/conversation-flow.html)

## 0. 品牌

- **名字**:manemu = 「まね(mane,模仿)」×「む(mu,夢)」。
- **一句話**:按住說話,manemu 模仿你的語氣、用對方的語言說出來——像夢裡忽然會說外語的那種流利。
- 文案裡「まね」用朱色(我方色)、「む」用藍染(對方色)——名字本身就是雙說話者色碼的縮影。
- wordmark:小寫拉丁 `manemu`(800 weight、+.04em)+ 假名 `まねむ` 次階(+.3em)。

## 0.5 登入前頁(v2.1 版式)

順序:wordmark → 品牌文案 → **Google 登入(上方,不被示範推走)** → 封測小字 →
「▶ 看 30 秒示範」→ 示範以**真氣泡元件**向下生長(自動捲動),內容固定演「拉麵店 + 一次誤聽→重講」
——讓訪客在登入前就看懂核心賣點(聽錯看得到、重講就好)。示範不開麥克風、不 call API。

目的:M3 前端的視覺與互動規範。mockup 已可互動(repo 內開檔即用,或 artifact 連結),
所有時序參數來自 harness 實測(findings §3.9、m3-spec.md),不是示意值。

## 1. 設計原則

1. **翻譯品質的不確定性是 UI 的一級公民**——災難率 0.7%(精準)/8%(快速)不是零,
   介面必須讓使用者「3 秒內發現並修復一次誤聽」。信心徽章、回譯展開、長按重講都是為此存在。
2. **戶外可讀**:旅行場景 = 大太陽下/居酒屋夜裡,雙主題都是實用需求,不是裝飾。
3. **半雙工誠實呈現**:播放譯音時 PTT 灰化——不假裝全雙工,防 echo 也防使用者疑惑。
4. **等待要有敘事**:預熱 0.5s、死氣 1.0s 都有明確狀態文案(「連線中…」「翻譯中…」),
   讓延遲讀起來是「步驟」而不是「卡住」。

## 2. 色彩系統

雙說話者色碼是資訊設計,不是裝飾——取自日本傳統色,對應旅行語境:

| Token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `--me` | #C0392B(朱・torii) | #E05A48 | 我方:氣泡、PTT、譯文字 |
| `--them` | #33587A(藍染) | #7BA3CC | 對方:同上 |
| `--paper` / `--ink` | #F6F7F5 / #1C2726 | #151D1C / #E8ECEA | 地/墨(冷灰偏綠,非純灰) |
| `--ok` / `--warn` | #2E7D4F / #9A6B00 | #63B588 / #D9A93F | **僅限**信心徽章與回譯框 |

語意色(ok/warn)與說話者色分離;accent 花在雙 PTT 上,其餘保持安靜。
主題切換:token 定義在 `:root`,`prefers-color-scheme` 換值,`data-theme` 覆寫兩個方向。

## 3. 字型

CJK 字型無法以 data URI 內嵌(體積),**刻意**採系統字族:
`"PingFang TC","Hiragino Sans","Microsoft JhengHei","Noto Sans TC","Noto Sans JP",system-ui`。
延遲晶片、時間數字一律 `font-variant-numeric: tabular-nums`。
面對面模式的對面文字 19px 加粗(隔著桌子要讀得到);氣泡內 STT 13px 次階、譯文 15px 主階。

## 4. 兩種版面模式

### 4.1 對談模式(bubble)
- 通訊 app 慣例:我右對方左;氣泡內兩層 = STT 逐字稿(次階)+ 譯文(主階、說話者色)。
- 氣泡角落 metadata:延遲晶片(實測秒數)+ 信心徽章(僅我方訊息)。
- 底部雙大 PTT:左朱「按住・我說中文」、右藍「押して話す」——方向手動固定,不做語言自動偵測(code-switch 實測會炸)。

### 4.2 面對面模式(face-to-face)
- 螢幕水平對切,**上半 `rotate(180deg)` 給對面的人**;各半有自己的 PTT 貼在「自己的下緣」。
- 同一份對話、兩側各以自己的語言完整呈現(自己說的=墨色大字,對方說的=次階)。
- 信心徽章**只出現在中文側**(確認流程是我方的事;對方只需要乾淨的譯文)→ mockup 開放問題 #1。
- 已重講的錯誤句在面對面側**直接隱藏**(對方不需要看到我的修正過程)。

## 5. 互動狀態機(PTT 一輪)

```text
idle ─按下→ 預熱(連線中…,0.5s;touch-start 即開 relay session)
     ─→ 聆聽(波形動畫 + STT 逐字上屏;快速模式譯文同步生長)
     ─放開→ 翻譯中(精準:~1.0s 死氣;快速:~0.25s)
     ─→ 播放譯音(🔊 提示;兩顆 PTT disabled = 半雙工防 echo)
     ─→ 徽章結算(✓ 意思一致 / ⚠ 確認一下→自動展開回譯)→ idle
```

- ⚠ 迴圈:回譯框顯示「對方聽到的意思:『…』」+ 提示文案;**長按氣泡 600ms** = 劃掉原句、
  解鎖重講。(開放問題 #3:或改為 ⚠ 框內直接給「重講」按鈕。)
- 劇本第 3 句固定重演實測災難「蝦子→瞎子」,用來測試使用者能否自行完成修復迴圈。

## 6. 文案規範

- 狀態文案寫「正在發生的事」:連線中/聆聽中/翻譯中/播放譯音(此時麥克風關閉)。
- 徽章:「✓ 意思一致」「⚠ 確認一下」——不用技術詞(不說「回譯」「置信度」)。
- 快速模式切換時的一句話警語:「快速模式反應更快,但更容易翻錯,請盯著確認文字」。

## 7. 開放問題(mockup 要回答的)

1. 面對面模式對方側要不要「翻譯中…」的過程提示?(目前:不給,只給結果)
2. 對談雙 PTT vs 面對面單側 PTT,哪個遞手機尷尬度低?
3. 重講入口:長按氣泡 vs ⚠ 框內按鈕?
4. 快速模式是否值得留在 v1?(災難 8%,強制展開回譯後的視覺噪音待評)
5. 面對面模式的 glossary/設定入口放哪(目前無)。

## 8. v2 增補(2026-07-29 使用者回饋)

### 8.1 面對面模式改版
- 兩側文字**同級**(19px 加粗),不再分主次;雙方都用**氣泡配色**(我=朱、對方=藍染),隔桌可讀、誰說的一眼可辨。
- 上半是完整鏡像:對他而言「自己說的」也用 me 泡呈現(色彩語意跟著視角走,不跟裝置持有者走)。

### 8.2 場景系統(左上)
- 預設「🧭 旅遊・通用」;可切「🆘 旅遊・緊急」;非旅遊場景(商務等)保留擴充位。
- 場景決定:空白引導例句、(未來)glossary 預載、劇本/prompt 的場域註記。

### 8.3 語言切換
- 對方語言可切(v2:日/英),**PTT 文案、面對面上半 UI、狀態文案全部跟著換**
  (押して話す ↔ Hold to speak)。介面語(中文)與對方語言是兩個獨立軸。

### 8.4 空白狀態引導(Ghost prompts)
- 開場空白時顯示灰字虛線框,引導使用者說出「人・事・時・地」完整句:
  - 通用:「我要一份〇〇,〇〇不要加」「請問〇〇在哪裡?」
  - 緊急:「我在(地點),我的同伴(狀況),請幫我(協助)」+ 求助/報案例句。
- 依據:實測短句+完整要素的句子 adequacy 最高;引導使用者說「好翻的句子」是免費的品質提升。

### 8.5 登入前/登入後(M3 真實架構,mockup 已演示)
- **登入前**:介紹頁 + 30 秒示範(預錄音檔真播放,**不開麥克風**、不能用自己的句子)。
- **登入**:Google SSO;登入後以 email 比對 **R2 白名單**(`r2://config/allowlist.json`),
  名單外顯示「等待受邀」頁。金鑰完全在 Worker 端,登入前後前端都不碰。
- **測試模式**(登入後,🧪 chip):橫幅逐句顯示 T50 語料請使用者照念,
  每句記錄(錄音、STT、譯文、延遲)寫回 R2 → 這就是 R1「真人語音驗證」的產品化收集管道。
